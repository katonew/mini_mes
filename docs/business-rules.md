# Mini MES Business Rules

- **문서 상태:** MVP 잠정 설계 기준
- **적용 시나리오:** 산업용 온도 센서 모듈 생산
- **적용 범위:** 품목 기준정보, 생산계획, 작업지시, 원자재 LOT 투입, 생산실적, 품질검사, 완제품 LOT 추적
- **정책 원칙:** BR-01~BR-05는 MVP 잠정 기준이다. BR-06은 1차 화면 구현 시 개발자가 확정한 품목 정책이다. 별도로 표시한 항목은 개발자 정책 결정 전까지 확정하지 않는다.
- **보완 근거:** 개발자가 추가 확정한 최종 품질검사 시점, LOT별 수량 구분, 생산실적 정정 및 원자적 처리 정책을 반영한다.

## 1. 문서 목적 및 적용 범위

이 문서는 `mini_mes_prd.md`의 요구사항을 후속 ERD와 Backend 설계에 사용할 수 있는 업무 규칙으로 구체화한다. 공장 자동화, 구매, 출하, 창고관리, 재작업 자동화는 이 문서의 범위에 포함하지 않는다.

이 문서의 수량은 서로 다른 의미를 가진다.

| 수량 | 의미 |
|---|---|
| 원자재 투입수량 | 특정 원자재 LOT에서 작업지시에 실제로 소비 확정한 수량 |
| 생산실적 생산수량 | 작업지시에서 생산 결과로 기록한 전체 수량 |
| 생산실적 양품수량 | 생산 과정에서 양품으로 기록한 수량 |
| 생산실적 불량수량 | 생산 과정에서 불량으로 기록한 수량 |
| 누적 생산수량 | 동일 작업지시·완제품 LOT에 연결된 생산실적의 생산수량 합계 |
| 누적 생산 양품수량 | 동일 작업지시·완제품 LOT에 연결된 생산실적의 양품수량 합계 |
| 누적 생산 불량수량 | 동일 작업지시·완제품 LOT에 연결된 생산실적의 불량수량 합계 |
| 최종 품질검사 전체 대상수량 | 작업지시 완료 시 확정된 누적 생산 양품수량 |
| 회차별 검사 대상수량 | 전체 검사 대상 중 해당 회차에서 검사한 수량 |
| 품질검사 합격·불합격수량 | 검사 결과별 수량. 회차별 값과 LOT 누적값을 구분한다. |
| 미검사수량 | 확정된 누적 생산 양품수량에서 누적 검사 합격·불합격수량을 뺀 수량 |

이하 품질검사는 최종 품질검사 등록 업무를 의미한다. Routing에 포함된 기능검사는 별도 공정이며, 그 공정 수행과 최종 품질검사 등록을 동일 업무로 취급하지 않는다. '완제품 LOT 수량'을 단일 값으로 사용하지 않고 조회·집계 목적에 맞는 수량명을 사용한다. 각 수량을 모두 DB 컬럼으로 저장할지는 정하지 않으며 원천 데이터와 집계 계산의 구분은 후속 ERD에서 결정한다.

## 2. 기준 제조 업무 시나리오

가상의 기준 제품은 **산업용 온도 센서 모듈**이다. 예시 원자재는 센서 칩, PCB 기판, 플라스틱 케이스다. 이 구성은 테스트와 데모를 위한 시나리오이며 제조업 전반의 보편 정책으로 해석하지 않는다.

업무 흐름은 다음과 같다.

```text
생산계획 → 작업지시 → 작업지시 시작
                     ↓
              원자재 LOT 실제 소비 확정
                     ↓
              생산실적 등록 및 누적
                     ↓
              작업지시 생산작업 완료
                     ↓
              품질검사 및 판정
                     ↓
              완제품 LOT 추적
```

## 3. 핵심 도메인 관계

- 생산계획은 여러 작업지시로 분할될 수 있다.
- 작업지시는 생성 시 적용 BOM 버전과 Routing 기준을 보존해야 한다.
- 하나의 작업지시에는 최대 하나의 완제품 LOT만 연결한다.
- 하나의 작업지시에는 여러 원자재 LOT이 투입될 수 있다.
- 하나의 작업지시에는 여러 생산실적이 등록될 수 있고, 모든 실적은 동일 완제품 LOT에 누적된다.
- 생산실적의 생산 양품과 품질검사 합격은 서로 다른 개념이다.
- 실제 LOT 추적은 현재 BOM이 아니라 저장된 원자재 투입 이력을 기준으로 한다.

### DB 유일성 제약 후보

- `work_order`와 완제품 LOT 연결 관계에는 작업지시 식별자의 유일성 제약 후보가 있다.
- 완제품 LOT 번호는 중복을 금지해야 한다. 번호의 전사 유일성 또는 품목별 유일성 범위는 **설계 결정 필요**다.
- 원자재 LOT 번호의 유일성 범위도 **설계 결정 필요**다.
- 유일성 제약은 애플리케이션 검증만으로 대체하지 않는다.

## 4. 작업지시 상태 전이

### BR-03. 작업지시 상태

잠정 상태는 `READY`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED`다.

허용 전이는 다음과 같다.

```text
READY ───────→ IN_PROGRESS ───────→ COMPLETED
  └──────────→ CANCELLED
```

규칙:

1. `READY`에서는 원자재 투입과 생산실적 등록을 금지한다.
2. `IN_PROGRESS`에서 원자재 투입과 생산실적 등록을 수행한다.
3. `COMPLETED`에서는 일반적인 추가 투입과 실적 등록을 금지한다.
4. 투입 또는 생산실적 이력이 있는 작업지시의 일반 취소는 금지한다.
5. `COMPLETED`에서 `READY` 등으로 임의 복귀시키지 않는다.
6. 잘못된 상태 전이는 화면이 아니라 서버에서 차단한다.
7. 생산 완료와 품질검사 합격은 별도의 상태와 사건으로 취급한다.
8. 생산실적이 존재하고 누적 생산수량이 0보다 크며 지시수량과 같을 때만 `COMPLETED` 전이를 허용한다. 생산 양품수량이나 검사 합격수량으로 완료를 판단하지 않는다. 지시수량 초과 생산은 금지하며, 생산수량 0 또는 지시수량 미달이면 완료를 거부한다.
9. 품질검사 완료나 합격은 `COMPLETED` 전이의 필수 조건이 아니다. 완료 시 미검사수량이 존재할 수 있다.
10. 최종 품질검사는 `COMPLETED`에서만 등록할 수 있다. `READY`, `IN_PROGRESS`, `CANCELLED`에서는 등록을 거부한다.
11. 검사 결과가 `FAIL`이어도 작업지시를 이전 상태로 자동 복귀시키지 않는다.
12. 일반적인 생산실적 정정은 `IN_PROGRESS`에서만 허용한다. `COMPLETED` 사후 정정은 MVP에서 제외한다.

## 5. 원자재 LOT 및 수량 관리

### BR-02. 원자재 LOT 투입 및 소비

1. `IN_PROGRESS` 상태의 작업지시에만 원자재를 투입할 수 있다.
2. 투입 품목이 해당 작업지시에 적용된 BOM의 구성 원자재인지 검증한다.
3. 원자재 LOT은 품목과 수량을 가진다.
4. 투입 등록은 실제 원자재 소비 확정으로 취급한다.
5. 투입 등록 시 원자재 LOT의 가용수량을 투입수량만큼 차감한다.
6. 원자재 LOT, 작업지시, 투입수량, 투입시각을 포함한 사용 이력을 별도로 보존한다.
7. 사용 이력 저장과 가용수량 차감은 동일 트랜잭션에서 처리한다.
8. 가용수량보다 큰 투입을 금지한다.
9. 동시 요청으로 가용수량이 중복 차감되지 않도록 DB 또는 트랜잭션 수준의 동시성 제어를 검토한다.
10. 원자재 투입과 생산실적 등록에는 요청 고유 ID를 사용하고 그 유일성을 DB 제약조건으로 보장한다. 동일 요청 재전송은 중복 반영하지 않고 서로 다른 정상 요청은 독립적으로 처리한다. 단순 시간 비교로 중복 여부를 판단하지 않는다. ID 저장 위치·유일성 범위·중복 요청 응답 방식은 기술 설계에서 결정한다.
11. 과거 소비 이력을 물리 삭제하지 않는다. `IN_PROGRESS` 작업지시에서만 일반적인 투입 정정·반환을 허용하고, 별도 이력으로 원래 투입과의 관계를 보존한다. `COMPLETED` 작업지시의 일반 반환·정정은 금지한다.
12. 실제 소비량과 BOM 기준 예상 소요량을 별도로 관리하고 차이를 조회할 수 있어야 한다. 실제 소비량을 BOM 계산값으로 자동 보정하지 않는다. 차이 자체는 MVP에서 자동 차단하지 않되, BOM에 없는 자재 투입과 가용수량 초과 투입은 차단한다.
13. 반환수량은 원래 투입과 연결된 반환 가능한 기존 순소비수량을 초과할 수 없다. 기존 소비·정정·반환 이력을 반영하여 잔여 순소비수량을 검증하며 소비하지 않은 자재를 반환 처리하지 않는다.
14. 반환 이력 저장과 원자재 LOT 가용수량 복원은 동일 트랜잭션에서 처리한다. 동시 반환 요청으로 반환 가능한 수량을 초과하거나 가용수량이 중복 복원되지 않도록 해야 한다. 이력 저장 구조와 동시성 제어 방식은 후속 설계에서 결정한다.

### 수량 예시

센서 칩 LOT의 가용수량이 100개일 때 60개 투입을 등록하면, 소비 확정수량은 60개이고 잔여 가용수량은 40개다. 같은 요청이 중복 처리되어 60개가 다시 차감되면 안 된다.

BOM 예상량이 센서 칩 100개이고 실제 소비량이 105개라면 차이 +5개를 조회한다. 해당 칩이 BOM 구성 자재이고 투입 당시 LOT 가용수량이 충분했다면 이 차이만으로 자동 차단하지 않는다. 실제 소비량은 105개로 보존한다.

가용수량 100개에서 60개를 투입하고, IN_PROGRESS에서 20개를 반환하면 반환 이력과 원래 투입의 관계를 보존하고 가용수량은 60개로 복원한다. 잔여 순소비수량은 40개다. 이후 50개 반환은 거부한다. 생산실적을 정정하는 것만으로 이 소비·반환 이력이나 가용수량을 자동 변경하지 않는다.

## 6. 생산실적 및 완제품 LOT

### BR-01. 작업지시와 완제품 LOT

1. 하나의 작업지시에서는 최대 하나의 완제품 LOT만 생성한다.
2. 작업지시 생성 시 완제품 LOT을 생성하지 않는다.
3. 최초 생산실적 등록 시 해당 작업지시에 연결된 완제품 LOT을 생성한다.
4. 동일 작업지시에 여러 생산실적을 등록할 수 있다.
5. 이후 생산실적은 최초 생성된 동일 완제품 LOT에 누적한다.
6. 작업지시와 완제품 LOT의 연결은 작업지시당 최대 1개가 되도록 DB 유일성 제약 후보를 식별한다.
7. 생산실적과 완제품 LOT의 연결 실패 또는 LOT 중복 생성이 발생하면 전체 등록을 성공으로 처리하지 않는다.
8. 하나의 작업지시에 여러 원자재 LOT이 투입되는 구조를 유지한다.

### 생산실적 수량 정합성

각 생산실적 행에 대해 다음을 만족해야 한다.

```text
생산수량 = 양품수량 + 불량수량
```

동일 작업지시·완제품 LOT에 연결된 생산실적의 생산·양품·불량수량을 각각 누적한다.

```text
누적 생산수량 = 누적 생산 양품수량 + 누적 생산 불량수량
누적 생산 양품수량 = 미검사수량 + 누적 검사 합격수량 + 누적 검사 불합격수량
```

두 번째 관계는 재검사·재작업·중복 검사 대상이 없는 MVP 기준이다. 생산 불량은 최종 검사 대상에서 제외한다. 원자재 투입수량은 원자재 품목별 소비 기록이므로 위 제품수량 합계와 직접 동일시하지 않는다.

첫 실적이 생산 60·양품 57·불량 3, 두 번째 실적이 생산 40·양품 38·불량 2이면 동일 LOT의 누적값은 생산 100·양품 95·불량 5다. 검사 전 미검사수량은 95이며 검사 합격수량은 0이다. 'LOT 수량 100'만으로 검사 대상이나 적합수량을 표현하지 않는다.

일반적인 실적 정정은 `IN_PROGRESS`에서만 허용하고 정정 이력을 보존한다. 정정 후 생산실적 누적값과 LOT 관련 집계의 정합성을 유지하며, 원자재 소비량은 자동 변경하지 않는다. `COMPLETED` 이후 및 품질검사 이후 일반적인 실적 정정은 금지한다. 실적 취소의 상세 절차와 집계 저장 방식은 **설계 결정 필요**다.

실적 등록·정정 후 누적 생산수량은 지시수량을 초과할 수 없다. 지시 100개에서 누적 생산 99개는 완료할 수 없고, 100개(양품 95·불량 5)는 생산 완료할 수 있으며 검사 대상은 95개다. 101개가 되는 실적 등록·정정은 거부한다. 생산실적이 없거나 생산수량이 0이면 완료할 수 없다. 생산실적 등록 재전송의 중복 방지는 BR-02 및 BD-07의 요청 고유 ID 정책을 따른다.

## 7. 품질검사 및 불량 관리

### BR-05. 생산실적과 품질검사

1. 생산실적은 생산수량, 양품수량, 불량수량을 기록한다.
2. 생산수량은 양품수량과 불량수량의 합과 같아야 한다.
3. 생산 과정의 불량과 품질검사에서 발견한 불합격을 별도 기록으로 구분한다.
4. 품질검사 불합격수량을 기존 생산실적의 불량수량에 무조건 합산하지 않는다.
5. 생산 양품은 생산 시점의 분류이고, 품질검사 합격은 검사 완료 후의 판정이다.
6. 미검사 제품을 합격으로 처리하지 않는다.
7. 회차별 검사 대상수량은 해당 회차의 검사 합격수량과 검사 불합격수량의 합과 일치해야 한다.
8. 검사 결과와 검사 대상의 이력을 보존한다.
9. 부분 합격을 수량으로 표현하며, 합격·불합격·미검사 누적수량을 각각 조회할 수 있어야 한다.
10. `PASS`/`FAIL` 판정 상태와 수량 정보를 구분한다. 부분 합격에 사용할 LOT 요약 상태명과 판정 매핑은 후속 설계에서 결정한다.
11. 재검사와 재작업은 MVP에서 제외한다.
12. 검사 등록은 작업지시 `COMPLETED` 이후에만 허용한다. 생산 완료와 검사 합격을 구분하며 검사 결과로 작업지시 상태를 되돌리지 않는다.
13. 전체 검사 대상은 작업지시 완료 시 확정된 누적 생산 양품수량이다. 생산 불량수량은 제외한다.
14. 여러 회차로 검사 결과를 등록할 수 있지만, 누적 검사수량은 확정된 생산 양품수량을 초과할 수 없다. 새 검사 대상수량은 미검사수량 이내여야 한다.
15. 누적 수량 상한 검증과 함께 동일 대상 수량의 중복 검사도 서버에서 방지한다. 상한 검증만으로 개별 대상의 중복 여부가 보장된다고 간주하지 않는다. 개별 검사 대상 식별의 필요성과 식별 단위, 중복 방지 DB 구조를 ERD에서 검토하며 여기서 구현 구조를 확정하지 않는다.

### 품질 수량 예시

```text
생산수량 100 = 생산 양품 95 + 생산 불량 5
품질검사 대상 95 = 검사 합격 92 + 검사 불합격 3
최종 적합수량 = 92
```

위 예시의 미검사수량은 0이다. 생산실적의 불량수량은 5를 유지하고 검사 불합격 3으로 덮어쓰거나 8로 자동 변경하지 않는다. 생산 불량을 검사 대상에서 제외하여 중복되지 않는 수량임이 보장되므로 전체 부적합수량 통계에서는 5 + 3 = 8로 집계할 수 있다. 최종 적합수량은 92다. 전체 부적합 8은 별도 통계값이다. 부분 합격 LOT의 수량은 구분하되 요약 품질 상태와 가용수량 모델은 **설계 결정 필요**다.

생산 양품 100인 완료 작업지시에서 1차 검사 60(합격 58·불합격 2)을 등록하면 미검사는 40이다. 2차 검사 40(합격 39·불합격 1)을 등록하면 누적 합격 97·불합격 3·미검사 0이다. 1차 이후 50개 요청 또는 2차 이후 10개 추가 요청은 잔여 검사수량을 초과하므로 거부한다.

불량 유형별 상세 합계가 생산 불량수량과 일치해야 하는지, 검사 불합격 상세를 별도 관리할지의 세부 구조는 **설계 결정 필요**다.

## 8. LOT 추적 규칙

### BR-04. LOT Traceability

완제품 LOT 조회 시 다음 정보를 확인할 수 있어야 한다.

- 작업지시
- 생산 품목
- 적용 BOM 버전
- 생산실적 목록과 수량
- 원자재 LOT별 실제 투입수량
- 원자재 투입 이력
- 원래 투입과 연결된 정정·반환 이력 및 반영 후 순소비수량
- 생산 불량 이력
- 품질검사 이력

규칙:

1. 현재 BOM을 사용해 과거 원자재 사용량을 추정하지 않는다.
2. 실제 저장된 원자재 투입 이력을 사용하며, 원래 소비 이력을 유지한 채 연결된 정정·반환을 통해 실제 순소비수량을 확인한다. 개별 생산실적에 사용량을 임의 배분하지 않는다.
3. BOM 버전 변경으로 과거 작업지시와 생산 이력이 변경되지 않아야 한다.
4. 작업지시 단위로만 원자재 투입이 기록된 경우, 개별 생산실적에 원자재 사용량을 임의 배분하지 않는다.
5. 조회 결과에 실제로 추적 가능한 범위와 추적 불가능한 세부 수준을 표시할 수 있어야 한다.
6. 원자재 LOT에서 작업지시와 연결된 완제품 LOT을 조회하는 정방향 추적의 MVP 포함 여부는 **설계 결정 필요**다.

## 9. 트랜잭션 및 데이터 정합성 원칙

- 최초 생산실적 등록·완제품 LOT 생성·연결은 원자적으로 처리한다. 하나만 저장되는 부분 반영을 허용하지 않는다. 서비스 메서드 경계와 잠금 방식은 후속 설계에서 결정한다.
- 원자재 사용 이력 저장과 가용수량 차감은 하나의 트랜잭션으로 처리한다.
- 수량 검증은 화면 검증만으로 끝내지 않고 서버와 DB 동시성 제어를 함께 검토한다.
- 작업지시 상태 전이와 관련 이력 저장은 허용된 상태에서만 처리한다.
- 원자재 정정·반환은 IN_PROGRESS에서만 별도 이력으로 원래 투입에 연결하며 원본을 물리 삭제하지 않는다. 반환 이력과 LOT 가용수량 복원은 동일 트랜잭션으로 처리하고 반환 가능한 순소비수량을 초과할 수 없다.
- 원자재 투입·생산실적 등록은 요청 고유 ID와 DB 유일성 제약으로 중복 반영을 막는다. 저장 위치·유일성 범위·중복 응답 방식은 기술 설계에서 결정하며 단순 시간 비교는 사용하지 않는다.
- 검사 시 작업지시 상태·확정된 검사 대상·미검사수량을 서버에서 검증한다. 동시 검사 요청도 누적 검사 상한과 대상 중복 금지 규칙을 지켜야 한다. 동시성 제어 방식은 후속 설계에서 결정한다.
- 생산실적 일반 정정은 `IN_PROGRESS`, 최종 검사 등록은 `COMPLETED`에서만 허용한다. 상태 전환과 동시 요청으로 이 경계가 깨지지 않도록 검토한다.
- 작업지시 완료는 누적 생산수량과 지시수량의 일치 및 생산실적 존재·0수량 금지를 검증한다. 동시 실적 등록·정정과 완료 요청으로 초과 생산이나 완료 후 변경이 발생하지 않도록 제어한다. 검사 대상은 완료 시 생산 양품수량으로 별도 확정한다.

## 11. 업무 의사결정 현황

BD 식별자를 유지한다. 누락되어 있던 승인 정책을 BD-01·02·04·07·09와 관련 BR에 반영한다. 업무 적용 정책과 후속 기술 설계 항목을 구분하며, 별도로 명시한 미확정 항목은 임의 확정하지 않는다.

적용 정책이 있는 항목의 '가능한 정책'은 비교했던 대안 기록이다. 실제 적용은 해당 항목의 적용 정책을 따르며 미채택 대안을 허용 규칙으로 해석하지 않는다.

### BD-01. 작업지시 완료 시 지시수량 100% 생산 여부

- 문제 상황: 작업지시를 언제 `COMPLETED`로 전환할지 기준이 필요하다.
- 가능한 정책: 지시수량 100% 생산 시에만 완료 / 미달 생산도 승인 후 완료.
- 적용 정책: 생산실적이 존재하고 누적 생산수량이 0보다 크며 지시수량과 같을 때만 COMPLETED 전이를 허용한다. 지시수량 초과 생산을 허용하지 않는다. 미달·0수량은 완료를 거부한다. 생산 양품·검사 합격수량으로 완료를 판단하지 않고 품질검사 결과와 생산 완료를 독립 관리한다.
- 권장 이유: 상태 전이와 계획 달성률이 함께 영향을 받는다.
- 데이터 정합성 영향: 완료 후 추가 실적 허용 여부, 계획수량 집계가 달라진다.
- 최종 결정 필요: 아니오. 완료 수량 기준과 초과 생산 금지는 확정.

### BD-02. 실제 소비량과 BOM 예상 소요량의 검증 기준

- 문제 상황: 실제 투입량이 BOM 계산량과 다를 수 있다.
- 가능한 정책: 초과·미달 모두 차단 / 범위 내 허용·범위 밖 경고 또는 승인 / 검증하지 않음.
- 적용 정책: BOM 예상량과 실제 소비량을 구분하고 차이를 조회한다. 실제값을 예상량으로 자동 보정하지 않는다. 차이 자체는 MVP에서 자동 차단하지 않는다. BOM에 없는 자재 투입 및 LOT 가용수량 초과는 차단하며 실제 투입 이력과 수량 정합성을 유지한다.
- 권장 이유: BOM은 예상량이고 실제 소비는 실행 결과이므로 같은 값으로 덮어쓰면 안 된다.
- 데이터 정합성 영향: 원가·재고·추적 결과의 해석에 영향을 준다.
- 최종 결정 필요: 아니오. 소비량 편차 자체의 자동 차단 금지와 기존 투입 검증 유지가 확정.

### BD-03. 생산실적 정정 및 취소 정책

- 문제 상황: 정정이 완제품 LOT, 품질검사, 집계에 영향을 준다.
- 가능한 정책: 완료 전만 수정 / 정정 이력 생성 / 기존 행 수정 금지 후 반대 거래로 보정.
- 적용 정책: 일반적인 생산실적 정정은 `IN_PROGRESS`에서만 허용한다. 정정 이력을 보존하고 누적수량·LOT 집계의 정합성을 유지한다. 정정으로 원자재 소비량을 자동 변경하지 않는다. 실적 취소의 세부 절차는 **설계 결정 필요**다.
- 권장 이유: LOT 추적과 감사 가능성을 유지할 수 있다.
- 데이터 정합성 영향: 누적수량, LOT 수량, 검사 대상수량을 재계산해야 할 수 있다.
- 최종 결정 필요: 정정 가능 상태·이력 보존·소비량 자동 변경 금지는 확정. 취소 상세는 필요.

### BD-04. 원자재 투입 정정과 재고 반환 정책

- 문제 상황: 소비 확정 후 잘못된 투입을 수정하면 가용수량과 이력이 함께 변한다.
- 가능한 정책: 반환 거래 생성 / 관리자 승인 후 정정 / 정정 금지.
- 적용 정책: IN_PROGRESS에서만 일반적인 투입 정정·반환을 허용한다. 소비 원본은 물리 삭제하지 않고 별도 정정·반환 이력을 원래 투입에 연결한다. 반환은 반환 가능한 기존 순소비수량 이내로 제한하며 소비하지 않은 자재를 반환 처리하지 않는다. 반환 이력 저장과 LOT 가용수량 복원은 동일 트랜잭션에서 처리한다. COMPLETED의 일반 정정·반환은 금지한다.
- 권장 이유: 실제 소비와 정정 사유를 분리해 추적할 수 있다.
- 데이터 정합성 영향: 가용수량과 원자재 사용 이력의 합계가 일치해야 한다.
- 최종 결정 필요: 업무 정책은 확정. 이력 저장 구조와 동시성 제어는 기술 설계에서 결정.

### BD-05. 완료 작업지시의 사후 정정

- 문제 상황: `COMPLETED` 이후 오류 발견 시 일반 수정으로 처리할 수 없다.
- 가능한 정책: 사후 정정 전용 절차 / 관리자만 허용 / 정정 금지.
- 적용 정책: `COMPLETED` 작업지시 사후 정정은 MVP에서 제외한다. 일반 실적 변경을 거부하며 상태를 임의로 복귀시키지 않는다.
- 권장 이유: 완료 시 확정된 생산 양품수량과 검사 이력을 유지한다.
- 데이터 정합성 영향: 완료 후 일반 실적 변경으로 LOT·검사 대상·생산계획 집계가 달라지는 것을 방지한다.
- 최종 결정 필요: 아니오. MVP 사후 정정 제외는 확정.

### BD-06. 부분 합격 LOT의 품질 상태 및 가용수량

- 문제 상황: 하나의 LOT에서 일부만 합격할 수 있다.
- 가능한 정책: 합격·불합격 수량을 별도 상태로 관리 / LOT 분할 / 부분 합격 미지원.
- 적용 정책: 부분 합격 LOT의 합격·불합격·미검사 수량을 각각 관리·조회한다. 모든 수량을 DB 컬럼으로 저장하는 것은 확정하지 않는다. 요약 상태명과 가용수량 모델은 **설계 결정 필요**다.
- 권장 이유: `PASS`/`FAIL` 하나만으로 수량 상태를 표현하면 정보가 손실된다.
- 데이터 정합성 영향: LOT별 누적 생산·검사 수량과 요약 품질 상태의 관계에 영향을 준다. 출하 기능은 이번 작업에 추가하지 않는다.
- 최종 결정 필요: 수량 구분은 확정. 요약 상태·가용수량은 필요. 저장·집계 구조는 ERD에서 결정.

### BD-07. 동일 요청 중복 처리 식별 기준

- 문제 상황: 네트워크 재전송으로 투입 또는 실적이 중복 등록될 수 있다.
- 가능한 정책: 클라이언트 요청 ID / 업무 키 유일성 / 서버 중복 시간창.
- 적용 정책: 원자재 투입·생산실적 등록에 요청 고유 ID를 사용하고 DB 제약조건으로 유일성을 보장한다. 동일 요청 재전송은 중복 반영하지 않고 서로 다른 정상 요청은 독립 처리한다. 단순 시간 비교로 중복 여부를 판단하지 않는다. ID 저장 위치·유일성 범위·중복 요청 응답 방식은 기술 설계에서 결정한다.
- 권장 이유: 수량 중복 차감과 중복 LOT 생성을 방지하려면 식별 기준이 필요하다.
- 데이터 정합성 영향: 원자재 잔량, 생산실적 누적, LOT 수량이 중복 반영될 수 있다.
- 최종 결정 필요: 요청 고유 ID 및 DB 유일성 보장은 확정. 구체적인 저장·응답 설계는 후속 결정.

### BD-08. LOT 생성 및 생산실적 등록 트랜잭션 경계

- 문제 상황: 최초 실적 등록 시 LOT 생성이 함께 발생한다.
- 가능한 정책: 하나의 서비스 트랜잭션 / LOT 선생성 후 실적 등록 / 실적 선저장 후 LOT 연결.
- 적용 정책: 최초 생산실적 등록과 완제품 LOT 생성·연결을 원자적으로 처리한다. LOT만 또는 실적만 남는 부분 반영을 금지한다.
- 권장 이유: 작업지시당 하나의 LOT이라는 제약을 안전하게 보장해야 한다.
- 데이터 정합성 영향: 생산실적과 LOT 연결 누락, 중복 LOT 생성 가능성에 영향을 준다.
- 최종 결정 필요: 원자적 처리는 확정. 서비스 경계·동시성 제어는 후속 기술 설계에서 결정.

### BD-09. 생산실적이 없는 작업지시의 완료 허용 여부

- 문제 상황: 생산실적 없이 작업지시를 완료하면 생산 이력이 없는 완료 상태가 된다.
- 가능한 정책: 항상 금지 / 0수량 완료 허용 / 취소로만 종료.
- 적용 정책: 생산실적 없는 작업지시와 0수량 작업지시는 완료할 수 없다. 완료 시 누적 생산수량과 지시수량의 일치를 검증한다. 완료 이후 일반 실적 추가·정정은 금지한다.
- 권장 이유: 상태 의미와 계획 달성률을 명확히 해야 한다.
- 데이터 정합성 영향: 완료 작업지시 수, 생산수량, LOT 생성 여부가 달라진다.
- 최종 결정 필요: 아니오. 생산실적 없는 완료 및 0수량 완료 금지는 확정.

### BD-10. 검사 완료 이후 생산실적 정정

- 문제 상황: 검사 결과가 존재하는 생산실적을 수정하면 검사 대상수량과 판정이 달라질 수 있다.
- 가능한 정책: 검사 완료 후 정정 금지 / 검사 무효화 후 정정 / 관리자 승인 정정.
- 적용 정책: 품질검사 이후 일반적인 생산실적 정정은 금지한다. 검사는 `COMPLETED`에서만 가능하고 일반 정정은 `IN_PROGRESS`에서만 가능하므로 두 시점은 겹치지 않는다. 재검사·재작업은 MVP에서 제외한다.
- 권장 이유: 확정된 검사 대상수량과 검사 이력을 유지한다.
- 데이터 정합성 영향: 검사 이력, 최종 적합수량, LOT 품질 상태가 영향을 받는다.
- 최종 결정 필요: 아니오. 일반 정정 금지는 확정.

## BR-06. 품목 기준정보 및 개발용 작성자

2026-10-23 개발자 확정 정책이다. 기존 item 테이블의 컬럼·제약을 변경하지 않는다.

### BR-06-01. 코드와 입력값

- 품목코드는 표시 가능한 ASCII 문자, 최대 50자이며 전체 품목에서 중복을 금지한다. 코드 대소문자를 임의 변환하지 않는다.
- 품목명은 필수이며 최대 200자다. 서버는 DB 컬럼 길이와 문자셋을 먼저 검증하고 DB의 절삭·변환에 맡기지 않는다.
- 품목구분 코드: RAW(원자재), SEMI(반제품), FINISHED(완제품). 신규 등록은 RAW·FINISHED만 허용한다. SEMI는 향후 확장용이며 MVP 등록 선택지에 제공하지 않는다.
- 관리단위 코드: EA(개·정수), M(미터·소수), G(그램·소수). 소수는 기존 DECIMAL(18,6) 설계를 따른다. 단위 자동 환산은 하지 않는다.
- 화면의 구분·단위 선택지와 서버 검증은 같은 enum 코드 정의를 사용한다. 품목 등록 화면에는 수량 입력을 추가하지 않는다. 정수·정밀도 검증은 후속 수량 업무에서 해당 단위에 맞춰 적용한다.
- 사용 여부는 1(사용), 0(미사용)만 허용하며 누락된 요청을 임의로 0 처리하지 않는다.

### BR-06-02. 변경 및 이력 보존

- 등록 후 품목코드·품목구분·관리단위는 변경 불가다. 품목명·사용 여부만 수정한다.
- 수정 요청의 불변 필드를 DB 원본과 비교하며 화면 readonly만으로 변경 금지를 보장하지 않는다. UPDATE에서도 불변 필드와 created_by를 변경하지 않는다.
- 물리 삭제를 제공하지 않는다. 미사용 변경은 기존 생산 이력·FK 참조를 삭제하거나 재연결하지 않는다.
- 미사용 품목은 신규 BOM 구성 및 신규 작업지시 대상에서 제외한다. 이번 작업에서는 해당 도메인을 구현하지 않으며 각 도메인 Service의 후속 검증 요건으로 유지한다.
- 명칭 변경은 현재 품목 명칭의 변경이다. 과거 화면의 당시 명칭까지 보존하는 스냅샷 기능을 이번 작업에 추가하지 않는다.

### BR-06-03. 작성자 및 저장 정합성

- 서버는 ActorProvider에서 MES_ACTOR_ID를 조회한다. 로컬 개발 예시는 LOCAL_DEV이고 인증된 사용자가 아닌 개발용 시스템 식별자다.
- Service는 작성자 누락·공백·64자 초과를 INSERT 전에 거부한다. 화면·요청 DTO에서 작성자를 받지 않는다.
- created_by는 등록 시에만 저장한다. 수정에 새 작성자 설정을 요구하거나 기존 created_by를 덮어쓰지 않는다.
- 향후 인증 도입 시 ActorProvider 구현에서 인증 사용자 ID를 제공한다. 현재 로그인·권한·사용자 테이블은 추가하지 않는다.
- 등록·수정은 각각 Service 트랜잭션이다. 중복 사전 조회를 통과한 동시 등록도 DB uq_item_code와 DuplicateKeyException 처리로 방어한다.
- 실패 시 성공 메시지로 처리하지 않는다. 입력값과 오류 안내를 제공하고 SQL·접속 비밀값은 화면에 노출하지 않는다.

### 정상·오류 시나리오

| 요청 | 결과 |
|---|---|
| MES_ACTOR_ID=LOCAL_DEV, SENSOR-001 / RAW / EA / 사용 등록 | created_by=LOCAL_DEV로 등록 |
| 같은 품목코드 재등록 또는 동시 등록 충돌 | 중복 오류, 두 번째 행 미생성 |
| SEMI 또는 미정의 구분·단위 신규 등록 | 서버에서 거부 |
| 코드·구분·단위 변경을 포함한 수정 요청 | 서버에서 거부, 기존 데이터 유지 |
| 명칭 변경 및 사용 여부 0으로 수정 | 기존 PK·코드·구분·단위·작성자·참조 관계 유지 |
| MES_ACTOR_ID 누락·공백 | 등록 거부, INSERT 수행 안 함 |

## BR-07. BOM 관리

2026-10-26 개발자 승인 정책이다. 기존 schema.sql의 테이블·컬럼·제약조건을 변경하지 않는다.

### BR-07-01. 등록과 수량

- BOM 코드는 표시 가능한 ASCII 문자 1~50자, 전체 BOM에서 유일하다. 대소문자를 변환하지 않는다. 버전 번호는 헤더 내 유일한 1~4294967295 정수다.
- 신규 헤더와 새 버전의 완제품은 활성 FINISHED·EA 품목이어야 한다. 기존 품목의 M·G 지원을 변경하는 것이 아니라 BOM 완제품 선택 범위만 제한한다.
- 기준 생산수량은 완제품 1 EA다. base_qty와 product_unit_code는 서버에서 설정하고 요청으로 입력받지 않는다.
- 구성 원자재는 RAW, 최소 1개다. 신규 구성에는 활성 품목만 허용한다. 동일 버전의 동일 원자재 중복은 Service에서 거절한다. 기존 DB에는 (version,item) UNIQUE가 없으므로 버전 부모 잠금을 모든 편집 경로가 공유해야 한다.
- required_qty는 양수이며 DECIMAL(18,6)의 최댓값 999999999999.999999 이하다. EA는 정수, M·G는 소수 6자리까지 허용한다. 범위/정밀도를 DB 변환 전에 검사한다.
- BOM은 예상 소요량이며 실제 소비량을 등록·보정하지 않는다. 단위 환산·서로 다른 품목이나 단위의 합산을 하지 않는다.

### BR-07-02. 수정 및 이력

- 등록된 BOM 코드, 완제품, 버전 번호, 기준 생산수량, 단위는 변경하지 않는다.
- first_used_at이 없고 작업지시 참조도 없는 버전만 기존 소요량 변경·원자재 추가를 허용한다. 기존 구성행 PK·품목·순번·작성자는 유지한다.
- 현재 미사용인 기존 구성은 신규 추가와 구분하여 보존하며, 미사용 버전의 기존 소요량 수정은 허용한다. 새 버전으로 옮길 때는 신규 구성으로 검증하므로 미사용 품목을 선택할 수 없다.
- 저장된 구성 제거·교체는 새 버전을 등록한다. BOM/버전/구성 물리 삭제 API와 SQL을 제공하지 않는다.
- first_used_at 또는 작업지시 참조 중 하나라도 있으면 모든 변경을 거절한다. 참조가 취소되더라도 사용 표시를 해제하는 기능은 제공하지 않는다.
- 기존 데이터의 base_qty가 1이 아니거나 제품 기준단위가 EA가 아니면 기존 수량을 재해석하지 않고 조회만 허용한다. 새 버전은 1 EA 기준으로 입력한다.
- 사용 여부는 이력 조회 정보이며 발행·활성 상태가 아니다. 수동 사용 표시 설정·해제, 다단계 구성, 손실률은 구현하지 않는다.

### BR-07-03. 저장 및 동시 요청

- 헤더·버전·구성은 Service 트랜잭션으로 원자 저장한다. 모든 변경 행수와 생성된 부모 ID를 확인하고 실패하면 롤백한다.
- 기존 BOM은 헤더 → 버전(수정 시) → 관련 품목 PK 오름차순으로 잠근다. 신규 헤더는 품목 PK 순서로 잠근 뒤 생성한다. 품목 활성 여부는 품목 잠금 후 검사하므로 품목 비활성화와 경쟁하여 신규 구성을 잘못 저장하지 않는다.
- 수정 요청은 잠금 후 저장된 상태·구성의 SHA-256 비교값과 제출값을 대조한다. 오래된 화면이나 변경 후 재전송은 오류로 응답한다. 비교값은 인증 수단이 아니다.
- 코드·버전 중복은 사전 검증과 기존 UNIQUE로 방어한다. 구성 추가는 같은 부모 잠금 아래 중복 품목을 재검증한다. 화면 버튼 비활성화와 저장 후 리다이렉트도 적용하나 DB/Service 검증을 대체하지 않는다.
- 신규 INSERT만 ActorProvider의 MES_ACTOR_ID를 요구한다. 기존 소요량 수정은 작성자를 덮어쓰지 않는다. 화면 작성자 입력은 없다.
- 폼 바인딩과 요청 크기 보호를 위해 한 버전 폼은 최대 256행으로 제한한다. 이는 소요량·생산 정책이 아닌 현재 화면의 기술적 입력 한도다.
- 현재 request_receipt는 생산 업무 전용 operation CHECK를 유지한다. BOM 요청을 끼워 넣거나 스키마를 확장하지 않는다.

## 12. 후속 설계 작업

1. BD 항목에서 확정된 정책을 유지하고 남은 업무 정책만 개발자가 결정한다.
2. 결정된 정책을 기준으로 작업지시·원자재 LOT·생산실적·완제품 LOT·품질검사 ERD를 작성한다.
3. 작업지시당 완제품 LOT 최대 1개, LOT 번호 유일성, 수량 정합성에 대한 DB 제약 후보를 확정한다.
4. 원자재 소비 차감·이력 저장과 최초 실적·LOT 생성의 원자성을 보장할 서비스 경계·동시성 제어를 설계한다.
5. 결정된 상태 전이와 예외 시나리오를 Backend Service 규칙과 수용 기준에 반영한다.
6. 검사 대상 식별·중복 방지 구조, 원천 수량 저장과 누적 집계 계산, 정정 이력 구조를 ERD에서 결정한다.
7. 요청 ID 저장 위치·유일성 범위·중복 응답 방식, 원래 원자재 투입과 정정·반환의 연결 구조 및 순소비수량 검증을 구체화한다. 누적 검사수량 상한과 개별 검사 대상의 중복 방지 검토를 구분한다.
