# Mini MES 공통 화면 및 품목 관리 구현 계획

> 실행 방식: 현재 세션에서 직접 구현한다. 개발자가 확정한 정책과 구현 계속 요청을 기준으로 진행한다. 빌드·테스트·린트·서버·브라우저·DB 변경·Commit·Push는 실행하지 않는다.

**목표:** Thymeleaf 공통 관리자 레이아웃과 실제 MyBatis 품목 조회·등록·수정 경로를 구현한다.

**구조:** 도메인별 모놀리스의 item 패키지에서 Controller → Service → Mapper를 연결한다. 화면 DTO와 DB 행 모델을 분리하며 업무 검증·트랜잭션은 Service에 둔다. 작성자 조회는 common의 ActorProvider로 분리한다.

**기술:** 기존 Java 17 / Spring Boot 3.5.16 / MyBatis / Thymeleaf, Bootstrap 5.3.8 CSS, Vanilla JavaScript. 새로운 Gradle 의존성은 추가하지 않는다.

**기준:** mini_mes_prd.md FR-01, business-rules.md의 품목 정책, schema.sql item 정의, 2026-10-23 개발자 확정 답변.

## 화면 구조 및 선택 이유

- 공통: 좌측 업무 메뉴, 상단 헤더, 본문, 성공·오류 메시지, 반응형 메뉴.
- 기준정보: 품목만 이동 가능. BOM·공정·Routing은 준비 중 표시.
- 생산관리: 생산계획·작업지시·원자재 투입·생산실적은 준비 중 표시.
- LOT·품질·추적: 원자재 LOT·완제품 LOT·불량·품질검사·LOT 추적은 준비 중 표시.
- 목록과 별도 등록·수정 페이지를 표준 MVC 폼으로 연결한다. 모달·Ajax 방식은 서버 오류와 입력 상태 관리가 추가되어 이번 구현에 사용하지 않는다.
- Bootstrap CSS를 로컬 정적 자원으로 제공한다. 브라우저의 외부 CDN 접속을 요구하지 않는다.

## 전역 제약

- DDL·기존 접속 설정·기존 테스트는 유지한다. 물리 삭제와 타 업무 구현은 제외한다.
- RAW·FINISHED만 신규 등록. SEMI는 코드로 정의하되 신규 등록 불가.
- 단위 EA·M·G. EA 정수, M·G는 기존 DECIMAL(18,6) 기준. 이번 품목 화면에는 수량 입력·환산이 없다.
- 등록 후 코드·구분·단위 변경 금지. 명칭·사용 여부만 수정한다.
- 작성자는 MES_ACTOR_ID, 로컬 예시는 LOCAL_DEV. 누락·공백이면 등록 거부. 인증 사용자로 표현하지 않는다.

## 검토 초점

1. 변조한 수정 요청: 화면 read-only 여부와 무관하게 Service가 불변 필드 변경을 거부한다.
2. 동시에 같은 코드를 등록: 사전 검사와 DB UNIQUE 예외 처리를 함께 둔다.
3. 작성자 누락·초과 길이: INSERT 전에 거부하고 작성자를 요청에서 받지 않는다.
4. 잘못된 품목구분·단위·사용 여부·문자열 길이·ASCII 코드: 서버 검증 후 저장한다.
5. 조회·저장 장애: SQL·비밀값을 화면에 노출하지 않고 입력값과 오류 안내를 제공한다.

## 정적 검토 기록

- Mapper XML을 외부 DTD 로딩 없이 파싱했다. Java 메서드 6개와 XML 문 ID가 일치하며 item 컬럼 9개가 기존 DDL에 존재한다.
- UPDATE에는 이름·사용 여부·수정 시각만 있다. INSERT의 작성자는 Service에서 설정한다. DELETE 및 raw SQL 문자열 치환은 없다.
- Controller의 메서드·URL 조합을 확인했고 4개 템플릿과 로컬 CSS·JS 참조가 존재한다.
- 독립적인 읽기 전용 코드 리뷰에서도 확정적인 오류는 발견하지 못했다. 컴파일·렌더링이 검증된 것은 아니다.
- Bootstrap 5.3.8 CSS를 공식 문서의 SHA-384와 대조했다. 출처: https://getbootstrap.com/docs/5.3/getting-started/download/
- .env는 Git 미추적·ignore 상태다. MES_ACTOR_ID=LOCAL_DEV를 추가했고 기존 값은 다시 쓰지 않았다. Gradle의 테스트 환경변수 전달 목록에도 이 식별자를 추가했다.
- 단위 테스트 소스는 작성했지만 빌드·테스트·린트·서버·브라우저·DB 작업은 실행하지 않았다. 테스트 통과·실제 화면 결과·동시성 검증 완료를 주장하지 않는다.
- 미사용 품목의 신규 BOM·작업지시 제외는 후속 도메인의 필수 요구사항으로 문서화했다. 이번 범위에 해당 도메인의 API·SQL을 추가하지 않았다.

## 개발자 확인 명령 및 화면

- DB를 모킹하는 신규 테스트만 검증: .\gradlew.bat test --tests "com.taehyung.mes.item.*"
- 위 명령은 이번 작업에서 실행하지 않았다. 기존 MySQL 연결 테스트는 별도로 유지한다.
- VS Code에서 Mini MES - Local Dev를 다시 시작한 뒤 /items를 연다. 등록·수정 검증은 별도 테스트 DB를 사용한다.
- MES_ACTOR_ID 누락 검증은 테스트 환경에서 해당 변수를 제거하고 프로세스를 다시 시작한 뒤 등록이 거부되는지 확인한다.
