# 작업지시 구현 계획

**범위:** 기존 DDL과 사용자 6차 요청 및 BD-01/02 승인에 따라 등록·목록·상세·시작·시작 전 취소를 구현한다. 완료 검증 구조는 준비하되 완료 UPDATE/버튼은 제공하지 않는다. 생산실적·LOT·소비 생성 없음.

**확정:** 신규 지시 수량은 1~999999999999 정수. Routing의 모든 현재 공정을 잠금 후 활성 검증, 미사용 공정이 하나라도 있으면 등록 거부. 기존 지시 진행은 현재 활성값으로 차단하지 않는다. BOM/Routing PK·제품 일치를 검증하고 최초 사용 시각은 기존 값 보존/NULL만 기록하며 지시 INSERT와 원자 저장한다.

**잠금:** 등록은 Plan → BOM 헤더 → Routing 헤더 → BOMVersion → RoutingRevision → Item(PK순) → Process(PK순). 기존 BOM 수정(BOM헤더→버전→Item), Routing 개정 추가(헤더→Item→Process) 및 계획 등록(Item)과 같은 상대 순서다. 시작/취소는 WorkOrder만 잠그고 실적/투입 이력을 재조회한다. 역순의 Plan/기준정보 잠금은 요청하지 않는다. 데드락·대기 실패는 전체 롤백 후 오류로 응답하며 부분 재시도/무조건 재등록하지 않는다.

**배분/재전송:** 모든 등록 지시 합계와 취소분을 구분 표시한다. 계획 초과는 정보성 안내만 제공한다. 업무 요청 키/UNIQUE가 없는 신규 지시의 재전송 멱등성은 임의로 확정하지 않는다. 1:N 등록은 가능하고 동일 상태 요청은 잠금/조건부 UPDATE로 한 번만 반영한다.
