# Routing 구현 계획

**목표/근거:** FR-04, 기존 DDL routing/routing_revision/routing_step 및 BR-08 공정 스냅샷/잠금 규약에 따라 등록·개정 추가·조회·등록 전 순서 편집을 제공한다. 기존 공정 작업의 미커밋 변경은 유지한다.

**정책 경계:** 미사용 개정 직접 수정은 기존 문서에서 미확정이다. 저장 개정의 UPDATE/DELETE API·SQL은 구현하지 않고 새 개정을 작성한다. 이를 미사용 수정 정책의 확정으로 해석하지 않는다. 최소 한 공정, 양의 UINT 개정/순서, 개정 내 순서 유일성을 검증한다. 순번의 연속성·같은 공정 ID의 유일성은 DB에 없는 제약으로 추가하지 않는다. 반복 실행·생략·병렬 업무 동작은 구현하지 않는다.

**구조:** RoutingController → RoutingService → RoutingMapper XML. 품목 잠금은 ItemMapper, 공정 잠금은 ProcessMapper, 작성자는 ActorProvider를 재사용한다. Routing 신규는 Item → Process PK순 잠금 후 저장, 기존 헤더의 새 개정은 Routing → Item → Process PK순으로 잠근다. 향후 작업지시의 상위 헤더/BOMVersion/RoutingRevision 잠금 순서와 함께 통합 검토한다.

- [x] Mock Service/Controller 테스트 작성(미실행). 정상·품목/공정 오류·순번/개정 중복·스냅샷·UNIQUE 경합·Spring 트랜잭션 롤백 호출·저장개정 쓰기 불가 포함.
- [x] Routing, RoutingRevision, RoutingStep 조회/저장 모델과 RoutingForm, RoutingStepForm, 예외·Mapper·Service 작성.
- [x] 목록/등록/상세/새개정 Controller·Thymeleaf·순서 이동 JS, 공통 메뉴/오류 연결.
- [x] 실제 MySQL 통합 테스트를 별도 명시적 opt-in 및 전용 로컬 테스트 스키마에서만 실행되도록 작성(미실행). 운영 OCI·일반 개발 DB 자동 연결 금지.
- [x] 문서·검증 안내 반영 및 독립 읽기 전용 리뷰와 정적 검토. 리뷰에서 확정적인 결함 발견 없음. 실행 성공 확인 아님.

**실행 제한:** 빌드·테스트·린트·브라우저·렌더링·개발서버·DB 실행 없음. 코드/테스트는 작성만 하며 통과를 주장하지 않는다. 커밋·push 없음.
