# 원자재 실제 소비 구현 계획

2026-10-27 승인 계약: 작성자 SHA-256 범위, UUID 키, v1 정규화 payload, 최초 성공 JSON, 서버 UTC 소비시각.

- [x] 입력·정규화·멱등성·업무 수량 테스트를 작성했다. 테스트 실행은 사용자 지침에 따라 생략했다.
- [x] lot 도메인에 소비 DTO/조회 모델/Receipt/결과 모델과 Mapper/XML을 추가했다.
- [x] 일반 Service와 별도 TransactionService 프록시로 신규 소비와 충돌 후 재조회의 REQUIRES_NEW 경계를 분리했다.
- [x] 신규 요청의 Receipt → WorkOrder → RawLot 잠금, 고정 BOM 관계·단위·수량 검증, 조건부 차감·소비 INSERT·성공 JSON의 단일 트랜잭션을 구현했다.
- [x] 목록·등록·상세 및 메뉴·작업지시 링크·공통 오류를 연결했다. GET 기준 조회와 POST 오류에 같은 UUID를 유지하고 POST 오류의 입력을 보존했다.
- [x] 전용 로컬 *_consume_test 스키마 opt-in 통합 테스트에 동시 재전송/재고 경쟁/상태 경쟁/단계별 실패/잠금 오류를 작성했다.
- [x] 승인 계약과 실제 잠금·집계·오류 처리를 업무/설계 문서에 반영하고 변경 범위를 정적 검토했다.

DB 스키마·의존성·원자재 반환·생산실적·완제품 LOT·품질 생성은 변경하지 않는다. 운영 DB 연결·빌드·테스트·서버·브라우저는 실행하지 않는다.
