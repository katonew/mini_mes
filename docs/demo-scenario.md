# Mini MES 포트폴리오 데모 시나리오

## 1. 목적과 준비 범위

산업용 온도 센서 모듈 100 EA의 생산을 통해 기준정보 → 작업지시 → 실제 원자재 소비·반환 → 실적·정정 → 생산 완료 → 최종 품질검사 → LOT 역추적 → 대시보드 흐름을 시연한다.

이 문서는 향후 화면에서 입력할 데이터와 예상 결과를 정리한 실행 안내다. 문서 작성 과정에서는 DB 접속·INSERT, 데이터 변경·삭제, SQL 시드 작성, 빌드·테스트·브라우저 실행을 하지 않았다. 아래 결과는 실행 결과가 아닌 기대값이다. 기존 코드·UI·스키마를 변경하지 않는다.

## 2. 시연 전 확인과 식별값 기록

- 향후 시연은 개발자님이 확인한 비운영 데모 환경에서 진행한다. 운영 OCI DB에 접근하지 않는다.
- 기존 데이터는 수정·삭제하지 않는다. 품목·공정·BOM·Routing 코드가 이미 있으면 필요한 명칭·단위·활성 여부·버전·구성이 모두 일치하는지 조회한다. 일치하는 기준정보만 재사용하고 불일치하면 시연을 중단하여 개발자님 결정을 받는다. 기존 데이터를 맞춰 고치지 않는다.
- 신규 등록을 권장한다. 기존 생산계획·작업지시·실적·소비 이력은 재사용하지 않는다. 기준정보 재사용은 위의 완전 일치 조건에서만 허용한다.
- 아래 LOT 번호는 입력 예시다. 화면 조회로 미사용을 확인한 뒤 사용한다. 중복이면 기존 LOT을 수정하거나 재사용하지 않고 개발자님이 새 번호를 정해 기록한다. 원자재 LOT 번호는 원자재 LOT 전체에서, 완제품 LOT 번호는 완제품 LOT 전체에서 각각 유일하다.
- 계획일은 예시 `2026-10-29`이며 실제 시연 계획일을 기록한다. 작업자·검사자 식별자는 예시 `DEMO-OP-01`, `DEMO-QC-01`을 사용한다. 시스템 작성자와 업무 담당자는 별개이며 생성 ID·시각·요청 키는 직접 지정하지 않는다.
- 같은 정상 업무를 반복 등록하지 않도록 성공 상세와 ID를 먼저 기록한다. 특히 생산계획은 같은 제품·날짜·수량만으로 재전송 중복 방지가 보장되지 않는다.

| 기록 항목 | 예시 또는 입력 방식 | 실제 식별값 |
|---|---|---|
| 환경 / 진행자 / 진행일 | 비운영 데모 환경 | 미기록 |
| 계획일 | 2026-10-29 | 미기록 |
| 작업자 / 검사자 | DEMO-OP-01 / DEMO-QC-01 | 미기록 |
| 생산계획 ID / 작업지시 ID | 등록 후 생성 ID | 미기록 |
| 센서 칩 LOT 번호 / ID | DEMO-TEMP-CHIP-001 / 생성 ID | 미기록 |
| PCB LOT 번호 / ID | DEMO-TEMP-PCB-001 / 생성 ID | 미기록 |
| 케이스 LOT 번호 / ID | DEMO-TEMP-CASE-001 / 생성 ID | 미기록 |
| 완제품 LOT 번호 / ID | DEMO-TEMP-FG-001 / 최초 실적에서 생성 | 미기록 |
| 센서 칩 최초 소비 ID / 추가 소비 ID | 서로 다른 소비 2건 | 미기록 |
| PCB 소비 ID / 케이스 소비 ID / 반환 ID | 등록 후 생성 ID | 미기록 |
| 1차 실적 ID / 정정 이력 ID / 2차 실적 ID | 정정은 1차 실적에 연결 | 미기록 |
| 1차 검사 ID / 2차 검사 ID | 같은 완제품 LOT에 연결 | 미기록 |

## 3. 화면 이동 순서와 단계별 입력

### 0단계 — 대시보드 기준값 기록

대시보드(`/dashboard`)에서 완료 작업지시 건수와 생산·양품·불량·검사 합격·검사 불합격 합계를 체크리스트에 기록한다. 다른 사용자의 입력 등 집계에 영향을 주는 동시 작업이 있는지도 기록한다. 전체 합계를 데모 한 건의 기대값과 동일시하지 않는다.

### 1단계 — 품목 등록

품목 관리(`/items`) → 신규 등록. 모든 품목의 사용 여부는 사용으로 지정한다.

| 구분 | 품목명 | 품목코드 | 단위 |
|---|---|---|---|
| 완제품(FINISHED) | 산업용 온도 센서 모듈 | FG-TEMP-001 | EA |
| 원자재(RAW) | 센서 칩 | RM-CHIP-001 | EA |
| 원자재(RAW) | PCB 기판 | RM-PCB-001 | EA |
| 원자재(RAW) | 케이스 | RM-CASE-001 | EA |

예상 결과: 활성 완제품 1종과 활성 원자재 3종을 후속 화면에서 선택할 수 있다. 기존 코드의 구분·단위를 임의 변경하지 않는다.

### 2단계 — 공정 등록

공정 관리(`/processes`) → 신규 등록. 다음 공정코드는 데모 입력 예시이며 사용 여부는 모두 사용으로 지정한다. 선택 설명에는 공정명을 동일하게 입력해도 된다.

| 공정코드 예시 | 공정명 | Routing 순번 |
|---|---|---|
| PROC-TEMP-01 | 부품 준비 | 1 |
| PROC-TEMP-02 | PCB 조립 | 2 |
| PROC-TEMP-03 | 센서 조립 | 3 |
| PROC-TEMP-04 | 기능검사 | 4 |
| PROC-TEMP-05 | 포장 | 5 |

예상 결과: Routing에 등록할 활성 공정 5개가 준비된다. 공정의 등록과 경로 지정은 실제 공정별 실행 실적을 기록했다는 의미가 아니다. Routing의 기능검사와 완료 후 최종 품질검사를 구분한다.

### 3단계 — BOM V1 등록

BOM 관리(`/boms`) → 신규 등록.

- BOM 코드: `BOM-TEMP-001`
- 완제품: `FG-TEMP-001`
- 버전 번호 입력값: `1`(V1)
- 기준 생산수량: 완제품 1 EA(서버 기준값)
- 구성 원자재와 필요수량: `RM-CHIP-001` 1 EA, `RM-PCB-001` 1 EA, `RM-CASE-001` 1 EA

예상 결과: V1 상세에 세 원자재가 각 1 EA로 표시된다. 100 EA 생산 기준 예상 소요량은 자재별 100 EA다. BOM 예상량과 실제 소비량은 별개이며 자동 소비·자동 보정하지 않는다.

### 4단계 — Routing Rev.1 등록

Routing 관리(`/routings`) → 신규 등록.

- Routing 코드: `ROUTE-TEMP-001`
- 완제품: `FG-TEMP-001`
- 개정 번호 입력값: `1`(Rev.1, 작업지시 선택 화면에서는 R1로 표시)
- 공정 행: 2단계의 공정을 순번 `1, 2, 3, 4, 5`로 선택

예상 결과: 부품 준비 → PCB 조립 → 센서 조립 → 기능검사 → 포장 순으로 저장된다. 저장된 공정명 스냅샷과 개정 연결을 확인한다.

### 5단계 — 생산계획과 작업지시 등록·시작

1. 생산계획(`/production-plans`) → 신규 등록: 완제품 `FG-TEMP-001`, 계획수량 `100`, 계획일은 준비 기록값. 생성된 생산계획 ID를 기록한다. 별도 계획코드·계획 상태·BOM·Routing 입력을 추가하지 않는다.
2. 작업지시(`/work-orders`) → 신규 등록: 방금 생성한 생산계획을 선택하고 **기준 조회**한다.
3. `BOM-TEMP-001 V1`과 `ROUTE-TEMP-001 R1`을 명시적으로 선택하고 지시수량 `100`을 입력한다. 최신 버전 자동 선택을 가정하지 않는다.
4. 저장 후 작업지시 ID와 `READY` 상태를 기록한다. 작업지시 상세에서 시작 처리하여 `IN_PROGRESS`를 확인한다.

예상 결과: 계획 100 EA에 작업지시 100 EA 한 건이 연결된다. 작업지시가 선택한 BOM 버전·Routing 개정을 보존하며, 아직 완제품 LOT과 생산실적은 없다. READY에서는 소비·실적을 등록하지 않는다.

### 6단계 — 원자재 LOT 등록

원자재 LOT(`/raw-material-lots`) → 신규 등록을 각각 진행한다.

| 원자재 | LOT 번호 예시 | 최초 등록수량 | 등록 직후 가용수량 |
|---|---|---:|---:|
| RM-CHIP-001 | DEMO-TEMP-CHIP-001 | 150 | 150 |
| RM-PCB-001 | DEMO-TEMP-PCB-001 | 150 | 150 |
| RM-CASE-001 | DEMO-TEMP-CASE-001 | 150 | 150 |

수량 단위는 모두 EA다. 실제 사용한 번호와 생성 ID를 기록한다. 최초 등록수량과 현재 가용수량을 구분한다.

### 7단계 — 실제 소비 4건과 반환 1건

원자재 투입(`/material-consumptions`) → 신규 등록에서 같은 IN_PROGRESS 작업지시와 해당 원자재 LOT을 선택한다. 각 행은 서로 다른 물리 소비 사건으로 별도 신규 등록한다.

| 순서 | 대상 LOT | 업무 | 입력수량 | 처리 직후 해당 LOT 가용수량 |
|---|---|---|---:|---:|
| 1 | 센서 칩 | 최초 소비 | 100 | 50 |
| 2 | PCB | 소비 | 100 | 50 |
| 3 | 케이스 | 소비 | 100 | 50 |
| 4 | 센서 칩 | 별도 추가 소비 | 10 | 40 |
| 5 | 센서 칩 | 4번 추가 소비 상세 → 반환 등록 | 10 | 50 |

반환 사유 예시: `추가 투입분 미사용 반환`. 최초 100 EA 소비가 아닌 **추가 10 EA 소비의 ID**에서 반환을 등록한다. 추가 소비의 성공 ID를 먼저 기록한 후 해당 상세의 반환 등록으로 이동한다.

예상 결과:

| 원자재 LOT | 소비합계 | 반환합계 | 순소비 | 최종 가용수량 | BOM 예상량과 차이 |
|---|---:|---:|---:|---:|---:|
| 센서 칩 | 110 | 10 | 100 | 50 | 0 |
| PCB | 100 | 0 | 100 | 50 | 0 |
| 케이스 | 100 | 0 | 100 | 50 | 0 |

- 센서 칩 소비 원본 2건과 추가 소비에 연결된 반환 1건을 모두 보존한다. 추가 소비 원본의 순소비는 0이다.
- 순소비 = 소비합계 − 반환합계, 가용수량 = 최초 등록수량 − 순소비다. 최초 등록수량은 150을 유지한다.
- BOM 구성 자재·가용수량·원소비별 반환가능수량을 검증한다. 예상량 초과만으로 별도 추가 소비를 금지하지 않는다.
- 소비와 재고 차감, 반환과 재고 복원은 각각 동일 트랜잭션의 업무다. 이번 문서 작성만으로 원자성·동시성의 실행 검증을 입증하지 않는다.

### 8단계 — 최초 생산실적과 완제품 LOT 생성

생산실적(`/production-results`) → 신규 등록 → 대상 작업지시 선택.

| 입력 항목 | 값 |
|---|---|
| 최초 완제품 LOT 번호 | DEMO-TEMP-FG-001 또는 준비 단계에서 기록한 새 번호 |
| 작업자 식별자 | DEMO-OP-01 또는 준비 기록값 |
| 생산 / 양품 / 불량 | 60 / 57 / 3 EA |

예상 결과: 최초 실적 1건과 완제품 LOT 1개가 함께 생성된다. 생성된 실적 ID·LOT ID를 기록한다. 상태는 IN_PROGRESS이며 누적 생산은 60 EA다.

### 9단계 — 1차 생산실적 정정

8단계의 실적 상세 → 수량 정정 화면에서 입력한다. 신규 실적 추가로 대체하지 않는다.

- 정정 후 생산 / 양품 / 불량: `60 / 55 / 5` EA
- 정정 사유: `기능검사 중 추가 불량 확인`

예상 결과: 동일 실적의 현재 수량은 60/55/5이고 정정 이력에는 변경 전 60/57/3, 변경 후 60/55/5와 사유가 남는다. 정정 이력을 누적 생산에 별도로 합산하지 않는다. 완제품 LOT은 추가 생성되지 않으며 원자재 소비·반환·가용수량은 바뀌지 않는다. 상세에서 정정 이력(`/production-results/{resultId}/corrections`)을 확인한다.

### 10단계 — 2차 생산실적 등록

생산실적 → 새 등록 화면 → 동일 작업지시 선택 → 생산 `40`, 양품 `38`, 불량 `2`, 작업자 식별자는 준비 기록값.

예상 결과: 기존 완제품 LOT을 재사용하며 후속 LOT 번호를 새로 입력하지 않는다. 현재 실적은 총 2건이고 누적 생산/양품/불량은 `100/93/7`이다. 정정 전 양품 57을 합산해 95로 표시하면 실패다. 지시수량 초과 생산은 금지한다.

### 11단계 — 작업지시 완료

작업지시 상세 → 완료 처리.

- 완료 기준: 실적이 존재하고 누적 생산수량 `100`이 지시수량 `100`과 일치한다.
- 예상 상태: `COMPLETED`
- 확정 최종 검사 대상수량: 누적 생산 양품 `93` EA
- 검사 전 검사 합격/불합격/미검사: `0/0/93` EA

완료는 양품 100 또는 검사 합격을 요구하지 않는다. 완료 후 일반 소비·반환·실적 등록·실적 정정은 하지 않는다. 완료 전후에도 같은 LOT과 같은 이력이 연결되어야 한다.

### 12단계 — 최종 품질검사 2회

품질검사(`/quality-inspections`) → 신규 등록 → 완료된 작업지시의 같은 완제품 LOT 선택. 두 번째 검사는 새 등록 화면에서 별도로 진행한다. 검사자 식별자는 준비 기록값이다.

| 회차 | 검사수량 | 합격 | 불합격 | 판정 사유 입력 예시 | 등록 후 미검사 |
|---|---:|---:|---:|---|---:|
| 1 | 60 | 58 | 2 | 최종 기능검사 1차 결과 | 33 |
| 2 | 33 | 30 | 3 | 잔여 대상 최종검사 결과 | 0 |

예상 결과: 검사 이력 2건, 누적 검사 93 EA, 합격 88 EA, 불합격 5 EA, 미검사 0 EA다. 각 회차 검사수량 = 합격 + 불합격이며 누적 검사는 확정 대상 93을 초과할 수 없다. 회차·시각은 시스템 결과를 확인한다. 실물 검사 대상이 겹치지 않도록 진행자가 구분한다. 요청 키·회차만으로 실물 중복 검사가 방지된다고 설명하지 않는다.

생산 불량 7 EA는 최종 검사 대상에서 제외하며 검사 불합격 5 EA와 별도로 표시한다. 검사 불합격으로 생산 불량을 12 EA로 덮어쓰거나 작업지시를 이전 상태로 돌리지 않는다. 요약 품질 상태명·출하 가용수량·재작업 정책은 이 데모에서 임의 결정하지 않는다.

### 13단계 — 완제품 LOT 역추적

완제품 LOT(`/finished-goods-lots`) → 기록한 LOT 상세 → 역추적(`/finished-goods-lots/{lotId}/trace`). 사이드 메뉴의 LOT 추적은 현재 준비 중 표시이므로 해당 메뉴의 활성화를 전제하지 않는다. 상세의 역추적 링크를 확인하고, 필요하면 기록한 실제 LOT ID로 위 경로에 이동한다.

1. 생산계획 ID·작업지시 ID·완제품 품목·COMPLETED 상태를 확인한다.
2. 작업지시에 저장된 BOM-TEMP-001 V1과 ROUTE-TEMP-001 Rev.1 및 공정 순서를 확인한다. 현재 최신 기준으로 과거 사용 관계를 추정하지 않는다.
3. 현재 생산실적 2건의 누적 100/93/7을 확인한다. 1차 실적 상세로 이동하여 정정 전후·사유·정정 이력을 확인한다. 역추적 본문에 정정 이력 전체가 직접 표시된다고 가정하지 않는다.
4. 소비 4건·반환 1건과 원소비 연결, LOT별 순소비 100·가용 50 및 BOM 예상량 차이 0을 확인한다.
5. 검사 이력 2건과 합격 88·불합격 5·미검사 0을 확인한다.

원자재 연결은 실제 저장된 소비·반환 이력을 사용한다. 작업지시 단위 원자재 소비를 개별 실적이나 개별 제품 1개에 임의 배분하지 않는다.

### 14단계 — 대시보드 반영 확인

대시보드(`/dashboard`)로 돌아가 0단계 기준값과 비교한다.

| KPI | 이 데모 한 건의 최종 기여량 | 다른 변경이 없을 때 전후 증감 |
|---|---:|---:|
| 완료 작업지시 | 1건 | +1건 |
| 누적 생산 | 100 EA | +100 EA |
| 생산 양품 | 93 EA | +93 EA |
| 생산 불량 | 7 EA | +7 EA |
| 검사 합격 | 88 EA | +88 EA |
| 검사 불합격 | 5 EA | +5 EA |

전체 DB에 다른 데이터가 있으면 화면 KPI는 위 값보다 클 수 있다. 전체 KPI가 위 숫자와 같다는 조건으로 합격 판정하지 않는다. 다른 변경이 없으면 전후 증감으로 확인하고, 동시 변경이 있으면 해당 LOT 상세 수량과 집계 범위를 함께 기록한다. 증감 원인을 분리할 수 없으면 대시보드 반영은 미확인으로 남긴다.

## 4. 최종 정합성 설명

```text
생산 100 = 양품 93 + 생산 불량 7
양품 93 = 검사 합격 88 + 검사 불합격 5 + 미검사 0
센서 칩 순소비 100 = 소비 110 - 반환 10
각 원자재 가용 50 = 최초 등록 150 - 순소비 100
```

센서 칩 최초 소비·추가 소비·반환과 실적 정정의 원본 연결을 보존한 상태에서 위 수량을 설명하는 것이 시연의 핵심이다. 실행 중 불일치가 생기면 이후 쓰기 작업을 중단하고 실제 ID·화면값·오류를 체크리스트에 기록한다. 기존 데이터를 직접 수정·삭제하거나 SQL로 맞추지 않는다.
