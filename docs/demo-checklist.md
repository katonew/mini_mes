# Mini MES 데모 실행 체크리스트

## 기록 원칙

현재 상태는 **전체 미실행**이다. `demo-scenario.md` 순서대로 향후 화면 시연할 때 기록한다. 문서 작성만으로 성공 표시하지 않는다. 이번 작업에서는 빌드·테스트·DB 접속·브라우저 실행을 하지 않는다.

- 판정은 `미실행 / 성공 / 실패 / 미확인` 중 하나로 기록한다.
- 성공: 해당 행의 기대값과 연결 관계를 실제 화면에서 확인하고 실제 ID·관측값을 기록했다.
- 실패: 기대값·수량·상태·이력 연결이 다르거나 업무 오류가 발생했다. 이후 쓰기 작업을 중단한다.
- 미확인: 환경·화면·기존 데이터 충돌 또는 동시 변경 때문에 판단할 근거가 부족하다. 성공으로 간주하지 않는다.
- 실패 해결을 위해 기존 데이터 삭제·직접 SQL 수정·스키마 변경을 하지 않는다. 필요한 결정과 원인 확인 내용을 기록한다.
- 정합성·이력 보존·트랜잭션의 실행 증거를 단순 화면 성공 표시로 대신하지 않는다. 별도 실패 주입·동시성 시험은 이 시연 범위에 없다.

## 5. 업무 규칙 설명 확인

아래는 시연 설명 및 정적 근거 확인 항목이다. 거부 요청을 실제 전송하거나 테스트를 실행하라는 지시가 아니다. 실행 증거가 없으면 서버 차단·롤백·동시성 검증 완료라고 표현하지 않는다.

| 규칙 | 판단 기준 | 확인 근거·실제 관측 기록 | 판정 |
|---|---|---|---|
| 상태 전이 | READY→IN_PROGRESS→COMPLETED. 소비·반환·실적·정정은 완료 전, 최종 검사는 완료 후 | 미기록 | 미실행 |
| 소비·반환 | 가용량 초과 소비와 원소비 잔여량 초과 반환 금지, 원소비·반환 연결 보존 | 미기록 | 미실행 |
| 실적 수량 | 생산=양품+불량, 누적 생산은 지시 100 초과 금지 | 미기록 | 미실행 |
| 완료 조건 | 누적 생산=지시수량, 검사 완료나 양품 100을 요구하지 않음 | 미기록 | 미실행 |

## 6. 최종 판단과 후속 기록

- 전체 데모 성공: 기능별 필수 항목과 수량·연결 관계가 실제 기록으로 확인되고 대시보드 반영 근거가 확보됨.
- 실패: 업무 수량·상태·연결·이력이 기대값과 불일치하거나 저장 오류 발생. 후속 진행을 멈추고 아래에 기록함.
- 미확인/미실행이 남으면 전체 성공으로 보고하지 않음. 미확정 업무 정책이나 기준정보 충돌은 개발자님 결정 필요.
